DataGEMS Croissant Extension Vocabulary

Namespace https://datagems.eu/ns/ · prefix dg: · version 0.5.0

A lightweight RDFS/OWL vocabulary that extends the MLCommons Croissant specification (which itself extends schema.org Dataset) with the metadata produced by the DataGEMS dataset profiler: dataset-level provenance and governance, per-column descriptive statistics and semantic type annotations, relational-database distributions, document-level (text/PDF) profiles, JSON / JSON Lines record-set profiles, and detected data quality errors.

Vocabulary (Turtle) JSON-LD context

Use the published context in a Croissant / JSON-LD document:

"@context": "https://datagems.eu/ns/context.jsonld"

or declare the prefix yourself, exactly as below, including the trailing slash:

"dg": "https://datagems.eu/ns/"

Classes

dg:ColumnStatistics

Column Statistics

IRI
https://datagems.eu/ns/ColumnStatistics

Descriptive statistics computed for a single tabular field. An instance is linked from a cr:Field via dg:statistics.

dg:DataQuality

Data Quality

IRI
https://datagems.eu/ns/DataQuality
See also
dqv:QualityAnnotation, dqv:QualityMeasurement, sh:ValidationReport

The outcome of data quality error detection over a single tabular record set. Carries a human-readable dg:summary and links to one dg:DataQualityError per detected error pattern. Detection only: the profiler reports errors, it never corrects the data. An instance is linked from a cr:RecordSet via dg:hasDataQuality.

Related but deliberately not equated: dqv:QualityMeasurement scores a resource against a dqv:Metric in a dqv:Dimension, and this carries no metric, dimension or score; sh:ValidationReport is the closest structural analogue (a report holding individual results) but is defined over RDF graph validation. Both are given as rdfs:seeAlso rather than rdfs:subClassOf, since asserting either would entail properties this class does not have.

dg:DataQualityError

Data Quality Error

IRI
https://datagems.eu/ns/DataQualityError
See also
sh:ValidationResult

One detected error pattern affecting one column of a tabular record set — not one erroneous cell. It names the affected column (cr:column), describes the pattern (sc:description), classifies it (dg:errorType), counts the affected rows (dg:totalAffectedRows) and carries up to five illustrative offending values (dg:examples).

Structurally this is the same idea as sh:ValidationResult — one finding, a message, a severity-like classification and a pointer to what it is about — but sh:focusNode and sh:resultPath address RDF nodes, while these findings address a column of a tabular file. Given as rdfs:seeAlso.

dg:DatabaseConnection

Database Connection

IRI
https://datagems.eu/ns/DatabaseConnection
Subclass of
cr:FileObject

A live relational-database distribution of a dataset. Its contentUrl carries a connection string (e.g. postgresql://host:port/database). Individual tables are represented as cr:FileObject resources that are cr:containedIn the connection and profiled as cr:RecordSet.

dg:JsonRecordSet

JSON Record Set

IRI
https://datagems.eu/ns/JsonRecordSet
Subclass of
cr:RecordSet

A cr:RecordSet describing the records of a JSON or JSON Lines file (or of a file set holding one JSON record per file). Its fields are cr:Field resources whose cr:source extracts values with cr:jsonPath, and fields under an array are marked cr:repeated. Carries the structure of the file: where the records are (dg:recordPath), its layout (dg:jsonShape), how many records it holds (dg:recordCount), how deeply they nest (dg:maxDepth) and how uniform they are (dg:schemaConsistencyPercentage).

dg:PdfRecordSet

PDF Record Set

IRI
https://datagems.eu/ns/PdfRecordSet
Subclass of
cr:RecordSet

A cr:RecordSet describing a PDF document, carrying extracted document metadata such as dg:author, dg:producer and dg:pagesCount.

dg:TextFileRecordSet

Text File Record Set

IRI
https://datagems.eu/ns/TextFileRecordSet
Subclass of
cr:RecordSet

A cr:RecordSet describing a plain-text file (or file set) profiled at document level rather than as columns. Carries size and readability statistics such as dg:numWords and dg:fleschKincaidGrade.

Properties of cr:Field

dg:sample

sample

IRI
https://datagems.eu/ns/sample
Domain
cr:Field
See also
cr:examples

A handful of values taken from the column, carried verbatim so their original type is preserved -- strings, numbers, booleans or nulls -- which is why no rdfs:range is asserted. Illustrative only: the values are not a statistically drawn sample and nothing should be computed from them. Distinct from cr:examples, which carries whole sample rows for a record set.

dg:semanticType

semantic type

IRI
https://datagems.eu/ns/semanticType
Domain
cr:Field
Range
xsd:string
See also
cr:dataType, csvw:propertyUrl

Short free-text semantic type of a tabular field, inferred from the column header and a sample of its values by the profiler's LLM-backed Column Type Annotator — for example "country name", "email address" or "identifier". Unlike cr:dataType, which gives the structural type (sc:Text, sc:Integer), this describes what the values mean. Two reserved values carry meaning: "unknown" when no type could be inferred, and "error" when annotation failed. An empty string means annotation did not run.

OVERLAP, KNOWN AND DELIBERATE: cr:dataType already carries semantic types. The Croissant specification allows a field to hold several dataType values provided at least one is atomic, the remainder supplying semantic meaning (its own example pairs sc:URL with a Wikidata entity). That is the correct home for this information. It is not used here because cr:dataType is declared "@type": "@vocab" and so needs an IRI, whereas these values are unconstrained English phrases produced by a language model ("geographic coordinate", "alternative label"). Once the values are drawn from a controlled vocabulary with IRIs they belong in cr:dataType, and this property should be deprecated rather than carried alongside it.

Properties of dg:DataQualityError

dg:errorType

error type

IRI
https://datagems.eu/ns/errorType
Domain
dg:DataQualityError
Range
xsd:string

Classification of the detected error pattern. One of: "format_inconsistency" (one format written several ways, e.g. mixed date formats), "value_error" (impossible or out-of-range values, e.g. a negative age), or "consistency_error" (one concept written several ways, e.g. "US" alongside "United States").

The set is closed and enforced at the source: the detection script is LLM-written and does occasionally invent a category, so entries carrying anything else are discarded rather than published. Plain missingness is deliberately excluded -- dg:missingCount and dg:missingPercentage already carry it -- while conditional emptiness is reported as a consistency_error.

dg:examples

error examples

IRI
https://datagems.eu/ns/examples
Domain
dg:DataQualityError

Illustrative occurrences of the error: an array of objects of the form {"value": "<erroneous value>", "row": <1-indexed row number>}, capped at five entries. Unlike dg:histogram, the profiler emits these as real JSON objects rather than a pre-serialized string; a consumer storing them in a property graph is expected to encode them itself.

Distinct from cr:examples despite the shared local name: that carries a record set's sample rows, as a JSON string, whereas this carries error occurrences as an array of objects. The domains keep them apart, but anything querying by property name across node types needs to know they differ in both meaning and type.

dg:recordPath

record path

IRI
https://datagems.eu/ns/recordPath
Domain
dg:JsonRecordSet
Range
xsd:string

JSONPath expression selecting the records within the file, e.g. "$[*]" for a root array or "$.stations[*]" for records wrapped inside a document. Every field's cr:jsonPath starts with it, so it can also be derived from the fields; it is stated once here so that consumers querying the file (for example with DuckDB read_json) need not reconstruct it.

Percentage (0–100) of records whose set of keys equals the most common set of keys. 100 means every record has the same structure; low values flag irregular files.
